## Context

目标打印机是拓竹 P1S（P1SC 套装），运行在局域网。它的能力边界与 X1 不同：

- 摄像头走 TCP 6000 的私有 MJPEG 协议，TLS，用户名 `bblp`，密码是 LAN Access Code；每帧是 16 字节头 + JPEG。社区实测约 1 fps、1280x720，固件对并发连接限制很严。
- 控制走 MQTT 8883（TLS，同样 `bblp` + Access Code），主题 `device/{serial}/request` 与 `device/{serial}/report`。`print.pause` / `print.resume` / `print.stop` 需要 `sequence_id`，并通过同 `sequence_id` 的 ACK 与后续 `gcode_state` 对账。
- 固件在云模式下会静默丢弃局域网写命令；控制需要 LAN Only Mode（部分固件还需要 Developer Mode）。代价是 Bambu Handy、云切片、外网访问不可用。
- P1 没有 X1 的本地 NPU 炒面检测；检测必须在 PC 上完成。
- PC 与 OpenClaw 同机，OpenClaw 通过飞书与用户交互；OpenClaw 可以调用本地 CLI。

v1 的目标是“无人值守时少漏检、误停可恢复”：先覆盖炒面/拉丝与首层大面积脱落；支撑倒塌样本不足，v1 只保留候选帧，不自动处置。系统不是消防/安全认证设备。

## Goals / Non-Goals

**Goals:**

- 常驻 daemon 独占摄像头与 MQTT，持续采集、检测、控制，并在异常时形成可审计的事件。
- 本地 ONNX 推理，1 fps 下 CPU 即可运行；不依赖云端。
- 候选与事件分离：候选层保召回，事件层控打扰。
- 确认异常后自动暂停，进入安全保持；60 分钟内等待用户决策，超时自动停止。
- 通过 OpenClaw/飞书推送文本 + 胶片条；用户用事件短码回复“继续/停止/误报/查看”。
- 提供一个只暴露高层动作的 CLI；OpenClaw 不接触原始 G-code/MQTT。
- 保存事件、胶片条、遥测、决策和误报标签，为长期降低误报提供数据闭环。
- daemon 在 OpenClaw/飞书不可用时仍能暂停、保持和超时停止。

**Non-Goals:**

- 从 PC 发起新打印、切片、FTPS 上传、AMS 映射。
- 支撑倒塌的 v1 自动检测与自动处置（只收集候选帧）。
- 明火/烟雾等安全认证级检测；建议独立烟雾报警器/智能插座。
- 云推理、多打印机、完整移动端 App。
- 保证零漏检或零误报；v1 以可解释、可回滚、可迭代为优先。

## Decisions

### 1. daemon 独占打印机，CLI 是薄客户端

**选择**：一个常驻 `smart-p1scd` 进程独占摄像头连接和 MQTT 连接；CLI 通过本地 IPC（Windows named pipe 或 localhost + token）调用 daemon。

**理由**：

- 摄像头并发连接有限，多客户端会互相踢下线；daemon 必须成为唯一持有者，并在本地重播。
- MQTT 写入需要统一分配 `sequence_id`、去重、重试和状态对账；多写入者会产生竞态。
- 事件状态机、60 分钟计时器、幂等和审计都需要一个单一事实源。
- OpenClaw 是 LLM，不能让它直接发布 MQTT 或发送原始 G-code。

**备选**：

- CLI 直接连 MQTT：实现简单，但无法保证单写入者、状态一致性和摄像头连接。
- OpenClaw 直接控制：灵活，但把 LLM 放进物理控制路径，审计和安全性都不可接受。

### 2. 摄像头：单连接 + 本地 MJPEG 重播

**选择**：daemon 连接 `:6000`，完成 80 字节认证包后按 16 字节头读取 JPEG；维护有界环形缓冲；在本机暴露 MJPEG/快照接口供用户和仪表盘查看。

**理由**：

- 保持唯一的打印机摄像头连接，避免把 Bambu Studio/其他客户端踢掉。
- 1 fps 下“视频”本质是帧序列；本地 MJPEG 足够做实时查看，胶片条足够做决策。
- 断流需要显式健康状态：连续 N 秒无帧标记 `DEGRADED`，并通知；是否在打印中暂停作为可配置策略（默认建议 5 分钟后暂停，见开放问题）。

**备选**：

- 让 Bambu Studio 持有摄像头，daemon 按需抓帧：会产生监控盲区，不可接受。
- 引入 pandaproxy 多路复用：增加部署复杂度，v1 不需要。

### 3. 检测：候选层 + 事件层

**选择**：检测管线分两级：

```
每帧 ──低阈值──▶ 候选（只进环形缓冲/日志，不推送）
                     │
                     │ 连续 N 帧 + 空间一致 + 增长/遥测/参考
                     ▼
                  incident（暂停 + 推送 + 等决策）
```

- 候选：`analyze(frame, context) -> [Candidate]`，字段包含类型、置信度、bbox/mask、帧号。v1 类型为 `spaghetti` 与 `first_layer_detachment`。
- 事件：滑动窗口内需要至少 K 帧正例，且 bbox IoU/空间聚类一致；可选“面积增长”提高严重度。首层使用更短窗口并以 `layer_num <= 1` 门控。
- 遥测门控：只在 `gcode_state == RUNNING` 时产生可处置事件；融合 `layer_num`、喷嘴/热床温度、`print_error`、`hms`。打印机已报告的堵头/断料走遥测告警，不重复造视觉检测。
- 模型：ONNX Runtime，v1 使用自采 P1S 画面训练 YOLOv8/YOLO11 三类检测器并导出单输出 ONNX，训练/导出/自检由 `smart-p1sc-model` 完成；模型版本随事件记录。1 fps 下 CPU 足够，GPU 可选。Obico 权重为双输出且许可不明，不纳入 v1。
- 支撑倒塌：v1 把“结构突变”候选打标为 `structural_anomaly` 并保存，不自动暂停；后续用同任务参考帧/逐层对比实现。

**理由**：

- 直接对单帧高阈值会漏检；直接对单帧低阈值会打扰。分层后召回由候选层保证，打扰由事件层控制。
- 1 fps 下 5-10 帧 = 5-10 秒，对炒面、首层大面积失败、支撑倒塌的后果可以接受。
- 自训练可控制三类标签、输出格式和数据许可；数据闭环持续补充误报/漏检样本。

**备选**：

- 纯 VLM 逐帧判断：延迟、成本、隐私都不合适；可作为后续人工复核/标注工具。
- 纯 CV 背景差分：工具头运动、打印件生长、光照变化导致误报高，不适合单独使用。

### 4. 事件状态机与 60 分钟安全保持

**选择**：

```
MONITORING
  │ 确认异常
  ▼
PAUSING ──ACK + gcode_state=PAUSE──▶ HOLDING (T0)
  │                                     │
  │ 暂停失败/被忽略                      ├─ 继续 ──▶ RESUMING ──▶ MONITORING
  ▼                                     ├─ 停止 ──▶ STOPPING ──▶ STOPPED
ESCALATE（重试 + 通知）                  ├─ 误报 ──▶ RESUMING + label
                                        ├─ T+10 提醒
                                        ├─ T+50 最后提醒
                                        └─ T+60 未回复 ──▶ AUTO_STOPPING ──▶ STOPPED
```

- 只有“异常导致的暂停”启动 60 分钟计时；手动暂停、断料暂停不启动。
- 暂停成功后喷嘴降到安全保持温度（默认 150°C，按材料可配），热床保持打印温度，腔体灯保持开启。
- 暂停命令失败：重试 3 次并通知；仍失败时按配置执行 fail-safe stop（默认对 P1 开启），避免失败打印继续。
- 60 分钟到点：发送 `print.stop`，验证状态，关闭加热；事件标记 `auto_stopped`，之后不能 resume。
- 计时器在 daemon 内，持久化截止时间；daemon 重启后恢复。OpenClaw/飞书不在关键路径。
- 决策与超时通过单 actor/事件循环串行化；用事件版本号做 compare-and-set。晚到的“继续”返回 `ALREADY_STOPPED`。
- 恢复后进入抑制窗口：同一区域/类型在窗口内不立即再次暂停；只有面积增长或新区域才升级。

**理由**：

- 无人值守时，漏检代价高；确认后默认暂停是更安全的选择。
- 60 分钟硬停满足“用户不回复按故障处理”，同时给用户留出查看和决策时间。
- 长暂停会带来喷嘴渗料、热床能耗和恢复接缝；降低喷嘴温度、保持热床是折中。

### 5. Operator 接口：OpenClaw/飞书 + CLI

**选择**：

- 推送：daemon 通过 OpenClaw Gateway 的 HTTP hook 发送结构化事件；OpenClaw 向飞书发送文本 + 胶片条图片。支持 OpenClaw 轮询 `incidents --open --json` 作为兜底。
- 决策：用户在飞书回复 `继续 7F3A` / `停止 7F3A` / `误报 7F3A` / `查看 7F3A`。OpenClaw 解析为 CLI 调用：
  `smart-p1sc incident decide INC-7F3A --action resume --code 7F3A --json`
- CLI 只暴露高层动作：`status`、`incidents`、`incident show`、`incident decide`、`incident label`、`snapshot`；不接受原始 G-code/MQTT。
- 输出稳定 JSON + 退出码（成功、状态不合法、需要确认、事件不存在、打印机不可达、已解决等）。
- 安全：CLI 通过本地 token 认证；OpenClaw tool policy 只允许调用该二进制；限流；所有调用写审计。
- OpenClaw 不可用：daemon 仍会暂停、保持、60 分钟自动停止；本机 CLI/状态页可作为兜底。
- 不把原始画面内容塞进 LLM 上下文；图片作为附件发送，元数据结构化。避免画面文字提示注入。

**理由**：

- 飞书回复 + 事件短码比自由文本可靠；多事件时不会操作错。
- CLI 给 OpenClaw 一个窄而明确的动作面，避免它直接接触打印机协议。
- daemon 独立于 OpenClaw，满足 fail-safe 而不是 fail-dependent。

### 6. 数据与数据闭环

**选择**：

- SQLite 存事件、帧索引、遥测快照、命令、决策、标签、作业身份；文件系统存胶片条/关键帧。
- 胶片条默认“前 10 帧 + 后 10 帧”；环形缓冲有界（如 120 帧）。
- 用户决策是弱标签：停止/误报是强信号，继续并最终完成也是信号；显式“误报”写入训练标签。
- 记录打印结果（完成/失败/被停止）作为最终标签；支持导出训练清单。
- 同任务参考帧：记录作业身份（如 3mf/gcode 哈希）与成功打印关键帧，v1 只存储，后续用于逐层对比。
- 保留策略可配（默认事件 30 天、普通延时摄影 7 天）；磁盘不足时先降级录制，不阻塞检测。
- 默认仅本地存储，不上传画面；日志中不出现 Access Code。

**理由**：

- 误报长期下降必须依赖真实数据，而不是反复手调阈值。
- 胶片条和遥测快照让用户在手机上可判断，也让后续标注有上下文。
- 本地存储符合隐私和“无云推理”的约束。

### 7. 部署与运行

**选择**：

- Windows 服务/开机自启运行 Python daemon；单实例锁；结构化日志；配置与密钥分离。
- Access Code 存 Windows Credential Manager/DPAPI 或环境变量，不写入仓库。
- OpenClaw 与 daemon 同机；CLI 加入 PATH；OpenClaw 使用受限 shell 工具/技能调用。
- 本地状态页提供打印机状态、检测器健康、开放事件、最新帧；与 MJPEG 重播同一 HTTP 端口。
- 时间统一用 UTC 入库，飞书消息用本地时间。

**理由**：

- 无人值守场景要求开机自启、崩溃恢复和可观测性。
- 同机部署让 CLI/IPC 简单，不需要额外网络暴露。

## Risks / Trade-offs

- [1 fps / 720p 的物理上限] → 只承诺大面积/结构性异常；胶片条辅助人工判断；不把明火安全交给它。
- [摄像头单连接] → daemon 独占 + 本地 MJPEG；用户不能同时用 Bambu Studio 看摄像头，需要在本地页面看。
- [LAN Only 失去 Handy/云访问] → OpenClaw/飞书补远程通知；文档写清楚切换成本；固件更新可能需要临时退出 LAN Only。
- [误报打扰] → 两级确认、遥测门控、恢复抑制、数据闭环；v1 初期可能偏保守，用标签逐步收敛。
- [漏检] → 候选层低阈值、P1 短确认窗口、60 分钟保持；仍无法保证零漏检。
- [误停代价] → 用户可继续；60 分钟自动停止；恢复抑制避免反复停。
- [长暂停导致渗料/接缝] → 喷嘴降温、热床保持；60 分钟硬停；文档说明恢复可能有接缝。
- [暂停/停止命令被静默丢弃] → ACK + `gcode_state` 双验证、重试、升级；暂停失败可 fail-safe stop。
- [60 分钟自动停止会取消打印且不能恢复] → T+50 最后提醒；事件结果明确；用户需重新发起打印（不在 v1）。
- [OpenClaw/飞书故障] → daemon 独立完成暂停/保持/超时停止；本机 CLI/状态页兜底；可选直连飞书 webhook。
- [PC 崩溃/断电] → 监控与通知同时失效；建议 UPS/智能插座/独立烟雾报警器；系统不是安全认证设备。
- [深色耗材/弱光] → 保持腔体灯开启；接受召回下降；数据中记录材料/光照，后续微调。
- [支撑倒塌与拉丝/模型相似] → v1 不自动处置；只收集 `structural_anomaly` 候选；后续用参考帧。
- [Prompt injection] → 不把原始画面文本送入 LLM；只发结构化元数据 + 图片附件；工具白名单。
- [Access Code 泄露] → 凭据管理器/DPAPI、TLS 固定、日志脱敏、控制接口仅本机。
- [Windows 休眠/更新重启] → 配置常开、开机自启、心跳与健康检查；部署文档写入 runbook。

## Migration Plan

这是新项目，没有既有代码迁移。

1. Phase 0：在真实 P1S 上验证摄像头、MQTT、暂停/恢复/停止、保持温度、腔体灯、OpenClaw/飞书。
2. Phase 1：部署 daemon 骨架，先以 notify-only 模式运行，不自动暂停。
3. Phase 2：开启自动暂停与 60 分钟自动停止；观察一周误报/漏检。
4. Phase 3：开启数据标注与模型迭代；再考虑支撑倒塌参考帧。

回滚：停止 daemon 即可；打印机仍可通过 LAN Only 的 Bambu Studio 使用。若需恢复 Bambu Handy，关闭 LAN Only（Access Code 会变化），并重新配置。

## Open Questions

- 飞书插件是否稳定支持图片附件、文本回复和群聊/私聊两种形态？Phase 0 验证。
- 安全保持温度按材料如何配置？默认 150°C 对 PLA/PETG 是否合适，ABS/ASA 是否需要更高？
- 摄像头断流 5 分钟后是否默认暂停？还是只通知？
- 暂停失败是否默认 fail-safe stop？对误报场景是否过于激进？
- 首层脱落的 v1 验收标准：只保证大面积失败，还是要求更细的翘边检测？
- 已决定自训练 YOLOv8/YOLO11 三类检测器并导出单输出 ONNX；Obico 权重因双输出不兼容、许可不明不纳入 v1。
- 同任务参考帧的作业身份如何获取：MQTT 是否提供文件名/哈希，还是需要从 FTPS/本地记录推断？
- 是否需要最小本地仪表盘（状态 + 实时画面 + 事件列表），还是 CLI + MJPEG 足够？
- 通知兜底是否要直连飞书 webhook，还是只依赖 OpenClaw？
- 60 分钟计时是否允许用户显式“延长 30 分钟”？当前设计是硬停。
